# AutoQuant 持久化模拟券商设计

- 日期：2026-07-22
- 状态：独立券商事实链、确定性成交适配器与双源账户投影已实施；协调器待实施
- 能力边界：无网络代码、无券商凭据、无真实资金能力、无 Web 下单入口

## 1. 独立事实来源

模拟券商不能把内部订单投影当作券商回报。schema v10 为每个已持久化且通过盘前风控
的模拟订单创建独立券商订单号、当前投影和追加写事实链。内部 `paper_order_events` 与
`simulated_broker_facts` 是两份独立记录，后续持续对账可发现回报丢失、进程中断或
内部消费失败，而不是比较同一份数据。

## 2. 成交语义

适配器只接受 `ApprovedPaperOrder`，并再次确认对应订单已经写入 schema v8。提交首先
生成 `submitted` 事实：

- 无限价的买单按 ask、卖单按 bid 全量模拟成交；
- 买入限价低于 ask 或卖出限价高于 bid 时保持 submitted；
- 休市状态直接拒绝调用，不伪造成交；
- 券商订单号由订单哈希确定，相同订单重复提交返回原事实，不重复成交；
- 本阶段不模拟队列位置、部分成交概率和流动性冲击，不能作为实盘成交质量证据。

## 3. 持久化与恢复

每个事实包含前序哈希和规范化回报哈希。事实禁止更新和删除；券商投影只允许序号加
一、时间前进、身份不变和终态不可逆。启动时从第一条事实重放全部受限订单，并把
重放结果与当前投影逐字段比较。任何差异都会中止启动并触发恢复失败停机。

## 4. 后续连接条件

内部订单历史与券商事实历史现在分别生成资金、按标的持仓、T+1 可卖量和未结订单。
投影以 `AQ_PAPER_INITIAL_CASH` 为起点，按全局成交时间应用累计成交增量；最低佣金按
订单累计费用只收取一次。行情标记、初始资金、订单和回报哈希、费用版本、截止时间
共同进入证据哈希。缺少持仓行情、现金为负、同日卖出或未来事实均会失败关闭。集成
测试证明回报尚未写入内部事实链时会产生稳定差异，消费完整回报后两份投影才会一致。

在开放模拟订单前仍需：

1. 在同一协调器中执行 kill switch、对账、行情时效、盘前风控、审计和模拟提交；
2. 对提交后崩溃、回报丢失、未知订单、重复回报和重启恢复进行故障注入；
3. 使用持续行情源运行足够长的模拟期并保存滑点、拒单和对账证据。

完成前 `gateway_available=false`，QMT 与真实交易继续硬锁。
