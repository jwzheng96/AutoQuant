# A 股分钟量化研究与执行系统设计

> **Historical naming record:** This document uses the former Open Quant identifiers.
> The current project name and supported interfaces are AutoQuant; see
> `docs/superpowers/specs/2026-07-22-autoquant-rename-design.md`.

- 日期：2026-07-21
- 状态：已由用户逐节批准，等待书面规格复核
- 市场：沪深主板、创业板、科创板；不含北交所
- 频率与持有期：分钟级信号与成交，典型持有 1–5 个交易日
- 路线：回测 → 模拟盘 → 分阶段资金实盘

## 1. 目标与不可承诺事项

系统目标是在 10% 账户最大回撤预算和无杠杆约束内，最大化扣除全部交易成本后的年化收益，并用工程控制尽量排除四类本金风险：

1. 数据泄漏和前视偏差；
2. 回测成交幻觉、过拟合与幸存者偏差；
3. 佣金、税费、滑点、冲击成本和容量遗漏；
4. 重复、越权、失控或状态不明的实盘下单。

系统不能保证持续高利润，也不能消除市场风险。完成标准是建立可复现、可审计、默认安全关闭的研究与执行链路，并以真实样本外数据持续检验净收益。

## 2. 已确认约束

| 项目 | 决定 |
|---|---|
| 数据接口 | RQData 历史/实时 API |
| 实盘接口 | XtQuant + MiniQMT + 券商 |
| Windows 节点 | 用户具备长期运行的 64 位 Windows 节点 |
| 初始资金 | 10 万–100 万元 |
| 账户最大回撤 | 10% 硬停线 |
| 市场范围 | 沪深主板、创业板、科创板 |
| 持有周期 | 1–5 个交易日 |
| 杠杆 | 首期禁止融资、融券和其他杠杆；以后独立审批 |
| 优化目标 | 在风险和容量约束内最大化扣费后年化收益 |
| Alpha | 多模型集成，按基线、机器学习、事件、集成器顺序交付 |
| 模拟盘放行 | 不按固定天数；使用统计证据和安全证据联合判定 |

## 3. 总体架构

采用模块化研究核心与隔离 Windows 交易网关：

```text
研究/控制节点（macOS 或 Linux）
├── RQData 采集器
├── 时点数据与质量校验
├── 特征、回测和多模型研究
├── 组合构建与一级风控
├── Control API 与策略制品注册表
├── ClickHouse：分钟、Tick、特征和仿真事件
└── PostgreSQL：实验、配置、订单意图和追加式审计日志
                │
                │ mTLS + 短期身份凭证
                ↓
Windows 执行节点
├── 二级硬风控
├── XtQuant 行情交叉校验
├── 委托状态机与幂等控制
├── 人工启用、熔断和紧急停机
└── MiniQMT → 券商
```

### 3.1 安全域

- 研究和策略代码不能导入或调用券商下单客户端。
- 研究域只能产生带版本、决策时间和证据摘要的 `OrderIntent`。
- Windows 网关只接受签名正确、未过期并通过一级风控的订单意图，且必须执行二级风控。
- 回测、模拟盘、金丝雀实盘和正式实盘使用不同身份、数据库命名空间和授权策略。
- 实盘启用使用短期人工授权租约，而不是单一布尔开关。
- 租约失效、状态不一致、行情过期或审计不可写时，默认停止新开仓；撤单和受控降风险仍可执行。

### 3.2 不可变发布单元

每次策略发布绑定：

- 策略制品内容哈希；
- Git 提交哈希；
- 数据清单和数据版本；
- 参数与特征定义哈希；
- 交易成本模型版本；
- 市场规则版本；
- 风控策略版本。

任何一项变化都会形成新的发布单元，不能覆盖已有记录。

## 4. 真实 API 与凭据配置

生产数据只来自 RQData 与 QMT。API 权限取得前可以实现接口契约、数据库、连接检查和失败路径，但真实行情集成测试必须明确显示为未执行，不能用随机数据冒充通过。

仓库只提供变量名和非敏感示例：

```text
RQDATA_USERNAME
RQDATA_PASSWORD
RQDATA_ENDPOINT
QMT_USERDATA_PATH
QMT_ACCOUNT_ALIAS
QMT_SESSION_ID
CONTROL_API_URL
CONTROL_API_CLIENT_CERT
CONTROL_API_CLIENT_KEY
```

- `.env`、证书、Token、资金账号和密码不得提交 Git。
- `QMT_ACCOUNT_ALIAS` 是内部别名，不是实际资金账号。
- 真实资金账号只保存在 Windows 节点的本地密钥环境中。
- 日志、异常和指标必须脱敏，不输出完整凭据、账号或证书内容。

## 5. 时点数据模型与质量门

### 5.1 数据时间

每条市场或参考数据至少包含：

- `event_time`：市场事件发生时间；
- `published_at`：供应商可证明的发布时间，未知时为空；
- `available_at`：实时数据为系统实际可用于决策的时间；历史回填数据为版本化可见性策略给出的最早保守可用时间；
- `ingested_at`：系统接收时间；
- `source`、`source_revision` 和内容哈希。

所有研究查询必须提供 `as_of`，并满足 `available_at <= as_of`。缺少 `as_of` 的研究查询直接拒绝执行。

实时数据使用实际接收证据确定 `available_at`。历史回填无法重建当年的真实网络到达时间，因此不得把本次下载时间伪装成历史可见时间，也不得无依据假定零延迟。其 `available_at` 由明确版本化的 `AvailabilityPolicy` 生成：分钟行情不早于分钟结束时间并叠加保守供应商延迟；公告和基本面优先采用可证明的发布时间，否则推迟到下一交易日开盘后。无法建立保守可见性规则的数据不能用于正式历史实验。

### 5.2 版本与修订

- 原始记录只追加，不覆盖。
- 供应商修订产生新版本，并关联旧版本与修订原因。
- 复权因子、公司行动、ST 状态、停复牌、上市/退市状态和板块归属按当时可知版本读取。
- 历史查询不得使用今天的证券状态回写过去。
- 每次实验生成不可变数据清单，包含区间、标的、版本、来源、质量报告和内容哈希。

### 5.3 分钟与实时数据

- 分钟 K 线在该分钟结束并实际到达系统后才能使用。
- 迟到、重复和乱序记录保留原始状态，由规范化层确定可见版本。
- RQData 与 QMT 实时价格、成交量或交易状态差异超过版本化阈值时，相关标的进入隔离区。
- 全市场数据延迟或冲突时停止新开仓。

### 5.4 质量检查

质量门覆盖：

- 交易日历、时区、交易时段与午休；
- 缺失、重复、乱序和非交易时段记录；
- OHLC 关系、负价格/成交量和异常跳变；
- 复权连续性与公司行动；
- 停复牌、涨跌停和证券状态；
- 标的覆盖率与跨源差异。

失败数据进入隔离区，不能静默进入正式实验或实盘信号。

## 6. 回测与成交模型

回测采用离散事件账本，并与实盘共享市场规则与订单状态语义：

```text
信号 → 目标持仓 → OrderIntent → 模拟交易所 → 成交/拒单/部分成交
                                            ↓
                               现金、持仓、费用和净值账本
```

### 6.1 时间与成交约束

- 使用某分钟数据形成信号后，最早只能在下一可交易事件申报。
- 禁止用同一分钟收盘价同时形成信号和成交。
- 只有分钟 K 线时，不假定知道盘口队列位置，不允许“价格触及即全部成交”。
- 分钟成交由参与率、估算点差、波动率、方向、限价和可用成交量共同决定。
- 获得 Tick 数据后增加逐笔回放，但不声称知道不可见的队列优先级。
- 停牌、涨跌停、价格笼子、流动性枯竭和卖出不可用会导致拒单或部分成交。

### 6.2 成交场景

每个实验同时运行：

- 基准场景：使用经真实数据校准的中位成本参数；
- 悲观场景：扩大点差与冲击、降低成交率、增加信号延迟；
- 压力场景：成本进一步上升，并模拟极端流动性与网络延迟。

只有基准盈利而悲观场景没有正收益证据的策略不能进入模拟盘。

### 6.3 成本与容量

逐笔成交计入：

- 券商佣金和最低收费；
- 卖方印花税；
- 过户费与监管费用；
- 买卖价差、滑点和市场冲击；
- 未成交、部分成交和机会成本。

费率按生效日期版本化，券商合同和实际交割单优先于默认值。当前印花税基线为卖出金额 0.05%，上线前必须通过券商交割单复核。

容量报告至少覆盖 10 万、25 万、50 万和 100 万资金规模，限制单票和分钟成交量参与率，并显示年化收益随资金增加的衰减。

### 6.4 市场规则

规则引擎按交易所、板块和生效日期处理：

- T+1 可卖数量；
- 交易时段、集合竞价、午休和盘后定价；
- 主板、创业板、科创板的涨跌幅和价格笼子；
- 申报数量、价格步长和最大订单；
- 新股、风险警示、退市整理、停复牌和无涨跌幅限制状态；
- 现金、持仓、分红送转和退市处置。

规则来源以交易所和中国结算生效文件为准，不把当前规则回填到历史时期。

## 7. 多模型研究与反过拟合

### 7.1 交付顺序

1. 可解释横截面基线：动量、短期反转、量价、流动性和风险过滤；
2. 机器学习挑战者：正则化线性模型和梯度提升树优先；
3. 事件模型：仅在对应 Point-in-Time API 权限和质量门完成后启用；
4. 集成器：只使用各模型真正样本外的预测和成交记录确定权重。

复杂模型必须对简单模型未解释的稳定残差提供样本外增益，否则不进入集成。

### 7.2 优化问题

最大化扣除全部费用后的年化收益，并同时满足：

- 回撤预算；
- 无杠杆与无融券；
- 单票、行业、板块和流动性暴露；
- 悲观成交场景的正收益证据；
- 10 万–100 万资金容量约束。

### 7.3 验证协议

- 使用嵌套滚动前推：训练集、调参验证集、锁定样本外集。
- 重叠标签按时间分组，执行 purge、embargo 和日期聚类重采样。
- 标签基于未来可实际成交区间，而非不可成交的同分钟价格。
- 所有特征、模型、参数和失败实验进入实验注册表。
- 相近参数搜索纳入多重检验，不把最佳单次结果视为独立证据。
- 锁定集一旦查看就不再用于调参；修改假设形成新研究代次。
- 集成器必须优于简单等权基线，并通过删减模型、成本加倍、成交率下降和信号延迟消融测试。

报告至少包含扣费前后年化收益、最大回撤、收益/回撤比、换手、成交率、容量、尾部损失、稳定性、拒单原因和数据质量。

## 8. 组合与账户风控

默认上限如下。系统允许调得更保守；任何放宽都需要新的风控版本和人工审批。

| 风险项 | 默认上限或动作 |
|---|---|
| 单票目标仓位 | 净值 5% |
| 单票硬上限 | 净值 7% |
| 单一行业 | 净值 20% |
| 创业板与科创板合计 | 净值 40% |
| 最低可用现金 | 净值 10% |
| 总持仓 | 净值 90% |
| 单笔订单 | 净值 2%，且不超过该分钟成交量 5% |
| 日内亏损 1.5% | 停止新开仓 |
| 日内亏损 2% | 只允许撤单和降低风险 |
| 策略回撤 5% | 风险预算减半 |
| 策略回撤 8% | 禁止新开仓，要求人工复核 |
| 账户回撤 10% | 账户级硬停机 |

风控动作不进行无条件市价清仓。流动性枯竭或跌停时进入受控减仓状态，并持续记录无法减仓的风险。

科创板只有在券商确认账户权限后进入可交易集合。权限不足、标的不可交易或账户状态未知时默认排除。

## 9. 受控执行与订单状态机

### 9.1 `OrderIntent`

订单意图必须包含：

- 全局唯一幂等键；
- 环境、策略和风控版本；
- 标的、方向、数量、订单类型和限价；
- 决策时间、创建时间、有效期；
- 目标仓位、最大数量和价格边界；
- 决策证据摘要与签名。

### 9.2 二级风控

Windows 网关在报单前重新检查：

- 实盘租约和调用身份；
- 可用资金、持仓和 T+1 可卖数量；
- 整手、价格步长、涨跌停和价格笼子；
- 单票、行业、板块、订单和亏损上限；
- 行情新鲜度和跨源一致性；
- 重复订单、自成交风险和账户权限。

### 9.3 状态机与恢复

订单状态至少包含待批准、已提交、部分成交、已成交、已撤销、已拒绝和状态未知。

- 每次状态转换追加审计事件，不覆盖历史状态。
- 超时不能直接重下；先主动查询券商状态。
- 重复、乱序回调通过券商订单号、幂等键和事件序号归并。
- 进程重启后先与券商资产、持仓、委托和成交对账。
- 对账不一致时禁止新单，直至人工或可证明的自动恢复完成。

### 9.4 人工与紧急控制

- 每个交易日实盘默认关闭。
- 有时限的人工授权租约明确环境、策略、账户别名和最大风险预算。
- 紧急停止直接作用于 Windows 网关，不依赖研究节点或数据库。
- 紧急停止后允许撤单和受控降风险，禁止新开仓。

## 10. 模拟盘与资金实盘晋级

模拟盘不使用固定日历天数作为唯一条件，必须同时满足：

- 扣费后单笔期望收益的单侧 95% 置信下界大于 0；
- 有效独立样本量达到事前功效分析要求；
- 实际滑点和拒单率未显著差于悲观回测假设；
- 模拟盘最大回撤低于 8%；
- 无重复下单、越权订单、状态漂移或未处理的数据质量告警；
- 收益不集中依赖单一月份、板块或少数股票。

满足条件只赋予申请下一级的资格，不能自动放行。

资金实盘分级：

1. 金丝雀：最多使用 10% 可配置资金；
2. 第二级：最多使用 25%；
3. 第三级：最多使用 50%；
4. 正式级：最多使用完整风险预算。

每次升级都要求新的样本外成交证据、无安全违规、滑点仍在悲观模型内和人工批准。盈利不能绕过安全门。

## 11. 故障处理与可观测性

### 11.1 默认失败行为

- RQData 限流：按官方限制退避并从检查点续传。
- 历史数据不完整：不得生成正式实验结果。
- 实时行情延迟、时钟漂移或跨源冲突：隔离标的或停止全市场新开仓。
- PostgreSQL、审计或风控服务不可用：关闭下单链路。
- 研究节点失联：网关维持成交回报、撤单和受控减仓，不接受新订单。
- 回调重复、乱序或丢失：依靠幂等和主动查询恢复。

### 11.2 监控与对账

监控至少覆盖：

- 数据延迟、缺口、隔离数量和跨源差异；
- 信号与订单延迟、拒单率、成交率和滑点；
- 仓位、行业、板块、流动性和亏损暴露；
- 订单未知状态、对账差异、授权租约和熔断状态；
- API、数据库、网关和 MiniQMT 健康状态。

开盘前、盘中定时和收盘后对账内部账本、QMT 与券商账户。

## 12. 测试与证据

### 12.1 测试层级

1. 单元与性质测试：时间可见性、费用、T+1、整手、涨跌停、现金守恒、非负持仓和幂等订单；
2. 数据库集成测试：时点查询、修订、事务、审计哈希链和故障恢复；
3. RQData 真实只读测试：字段、时区、限流和样本完整性；
4. Windows QMT 真实只读测试：行情、资产、持仓、委托和连接恢复；
5. 模拟盘端到端测试：真实行情驱动完整订单状态机与对账；
6. 故障演练：重复回调、进程崩溃、网络分区、数据库中断、迟到行情和时钟偏移；
7. 金丝雀实盘：全部统计门、安全门和人工审批通过后才启用。

合成边界数据仅用于证明涨跌停、部分成交、重复回调等安全不变量，不能用于研究绩效或收益宣传。

### 12.2 必须持续成立的不变量

- 研究查询不能看到 `available_at > as_of` 的数据；
- 账本现金、持仓和费用守恒；
- 无杠杆环境不能出现负现金或负持仓；
- 相同幂等键最多产生一笔券商委托；
- 所有成交都能追溯到订单意图和不可变策略版本；
- 未通过二级风控的订单不能到达 XtQuant；
- 状态未知时不能自动重下；
- 实盘租约无效时不能新开仓。

## 13. 分阶段交付

本文件是全系统总体设计，不作为单个超大实施计划。每个阶段在启动前形成独立的详细规格、实施计划和验收证据；后续阶段不得因为接口预留而被视为已经实现。下一份实施计划只覆盖阶段 1，并以能够独立证明时点数据不变量为完成边界。

### 阶段 1：可信数据基础

- 仓库、配置与密钥契约；
- PostgreSQL 和 ClickHouse 模式；
- RQData 真实适配器；
- 时点查询、版本修订、数据质量门和实验数据清单。

### 阶段 2：可信回测基线

- 离散事件账本；
- A 股版本化交易规则；
- 成本、部分成交、压力场景和容量模型；
- 可解释横截面基线策略。

### 阶段 3：多模型研究

- 机器学习挑战者；
- 事件数据与事件模型；
- 实验注册表、滚动验证、多重检验和集成器。

### 阶段 4：模拟执行

- Windows XtQuant 网关；
- 双层风控、订单状态机和对账；
- 真实行情模拟盘与故障演练。

### 阶段 5：受控资金实盘

- 统计放行；
- 10% 金丝雀资金；
- 25%、50% 与完整风险预算逐级晋级；
- 持续监控、复核和降级。

## 14. 外部依赖与完成边界

以下外部条件由用户后续提供，缺失时不阻止安全核心实现，但会阻止对应真实集成验收：

- RQData 账户与分钟、Tick、Point-in-Time 数据权限；
- 支持 MiniQMT 的券商账户和 XtQuant 权限；
- Windows 节点访问方式、MiniQMT 安装和账户别名；
- 券商佣金、最低收费和实际交割单；
- 科创板、创业板等账户交易权限。

没有这些证据时，系统不能宣称真实 API、模拟盘或资金实盘阶段已经完成。
