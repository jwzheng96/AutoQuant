# 模拟盘交易时段、连续行情与调度证据设计

- 日期：2026-07-23
- 状态：核心、schema v13 证据链、QMT 行情标准化和 schema v14 进程租约已实现；
  Windows 外部连接与生产部署未接线
- 边界：仅驱动持久化模拟券商，真实 QMT 提交和撤单继续代码级硬锁

## 1. 交易时段

调度器必须同时拥有上海时区的当前时间和在该时点已经可见的 `TradingSession`。日期不
匹配、日历证据来自未来或日历不可用时，不能仅凭工作日猜测开市。

股票竞价阶段按版本 `cn-equity-auction-hours-2026-v1` 分类：

- 08:45–09:15：系统盘前窗口，只允许冻结当日模拟账户开盘状态；
- 09:15–09:25：开盘集合竞价；
- 09:25–09:30：集合竞价结束后的暂停窗口；
- 09:30–11:30、13:00–14:57：连续竞价；
- 11:30–13:00：午间休市；
- 14:57–15:00：收盘集合竞价；
- 其余时间或交易日历休市：关闭。

当前模拟成交模型没有集合竞价队列和撮合细节，所以策略意图只在两个连续竞价窗口内
进入协调器。集合竞价阶段只观测，不下单，避免以错误成交模型制造虚假收益。

交易时间依据：

- [上海证券交易所交易规则（2026年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)
- [深圳证券交易所交易时段概览](https://www.szse.cn/English/services/trading/tradOverview/)

## 2. 连续行情边界

`ContinuousQuoteBook` 不把“最后一个价格”自动视为可信行情：

1. 连接或恢复后必须加载包含完整标的集合的显式基线；
2. 后续本地源序号必须连续，精确重复才幂等；
3. 跳号、同序号冲突、事件时间或接收时间倒退会使整条流失效；
4. 快照要求所有配置标的存在、未过期、不来自未来，并由行情明确报告开市；
5. 失效后不能用后续增量自愈，必须重新加载完整基线；
6. 快照将行情哈希、源游标、基线 ID 和观察时间提交为证据哈希。

`QmtWholeQuoteBridge` 已按 XtData 官方契约实现这个边界：

1. `get_full_tick` 基线必须精确覆盖配置交易池，基线不完整或包含意外标的时拒绝；
2. 供应商回调线程只复制不可变事实到有界队列，不查询账户、不写数据库、不运行策略；
3. 消费端为每个标准化观察分配连续本地序号，再串行发布到 quote book；
4. `time` 严格按毫秒时间戳转换，价格从 `lastPrice`、`bidPrice[0]`、`askPrice[0]`
   读取；缺失、非有限、零值或盘口倒挂均拒绝，不以最新价代替缺失盘口；
5. `market_open` 同时要求可信交易时钟处于连续竞价且 `stockStatus=13`，不能只靠供应商
   状态或墙上时钟单独推断；
6. 队列溢出、异常标的、格式错误或批次被消费上限拆分时，整条流失效并要求新基线。

字段和回调结构依据
[XtQuant.XtData 行情模块](https://dict.thinktrader.net/nativeApi/xtdata.html)。当前模块不导入
XtQuant，也不在 macOS 主机连接 MiniQMT；真实回调仍必须在获授权的 Windows 节点验证。

## 3. 调度顺序

每个 tick 按以下顺序失败关闭：

1. 确保持久化停机开关存在，默认 active；
2. 读取 point-in-time 交易日历并分类市场阶段；
3. 盘前先重放当日 session-risk 链；尚未初始化时才读取带来源哈希的全量 marks，并调用
   `PaperSessionInitializer`；
4. 连续竞价时，active 停机开关直接返回 `locked`，不读取行情、不运行策略；
5. 停机开关已由证据化人工流程复位时，先重放 session-risk，再获取完整新鲜行情；
6. 策略输出必须受每周期最大订单数、唯一 client order ID、固定 tick 时间、交易池、
   标的规则和风险策略约束；
7. 每个意图串行交给 `PaperOrderCoordinator`，由其跨进程账户锁、风险决策、券商事实和
   前后对账完成最终控制；
8. 调度周期必须写入证据 sink；落库失败立即激活停机开关并终止常驻循环。

调度器不会复位停机开关，也没有 Web 下单或启动入口。

## 4. schema v13 审计链

`paper_scheduler_events` 保存：

- 策略 ID、交易日、阶段、时钟规则版本和 point-in-time 日历哈希；
- 盘前 marks、实时行情快照、停机开关状态；
- 初始化状态、对账报告、每笔风控决策、订单投影、券商更新的哈希；
- 周期结果、稳定错误码、前序事件哈希和完整 cycle payload。

同一账户的 append 由 PostgreSQL advisory lock 串行化，重复 cycle hash 幂等；倒序时间
拒绝。事件禁止 UPDATE/DELETE，物化游标只能逐一递增。控制台启动和状态接口会重放整条
链，并在不一致时激活 `recovery_failed`。

## 6. schema v14 常驻进程所有权

`paper_scheduler_leases` 以账户为唯一所有权边界：同一账户即使策略 ID 不同，也只能有一个
未过期持有者。获取和接管由 PostgreSQL advisory lock 串行化；令牌只保存 SHA-256，
TTL 不超过五分钟，续租必须匹配账户、策略、持有者和令牌。过期后新进程以更高 generation
接管，旧进程不能续租或释放。

获取与释放写入不可 UPDATE/DELETE 的哈希事件链，续租只推进带版本的物化心跳。
`LeasedPaperSchedulerRunner` 在启动 scheduler 前获取租约，并以小于 TTL 的周期续租；
租约丢失、心跳存储失败或退出时无法证明释放，都会激活持久化停机开关并终止进程。

因此 schema v13-v14 证明调度、证据和单进程所有权边界可审计，不证明策略盈利，也不授权
实盘。
