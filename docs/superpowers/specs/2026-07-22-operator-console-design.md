# AutoQuant 运营控制台设计

- 日期：2026-07-22
- 状态：已实施并通过自动化与真实数据链路验收
- 边界：可信数据运营，不启用模拟或实盘交易

## 1. 目标

为阶段 1 数据基础提供仅监听本机的 Web 控制台，使操作员能够：

- 查看 PostgreSQL、ClickHouse 与 Tushare 配置/健康状态；
- 查看日线、复权因子、质量报告、数据清单和采集检查点摘要；
- 查询单只证券的日线历史；
- 提交范围受限、可审计的 Tushare 日线采集任务；
- 查看任务状态和脱敏后的结果；
- 明确看到交易能力尚未接入，而不是显示虚构订单或收益。

## 2. 安全边界

- 默认只绑定 `127.0.0.1`，远程访问必须使用 SSH 端口转发或受控反向代理；
- 所有业务页面和 API 使用常量时间比较的 HTTP Basic 凭证；
- 写操作额外要求同源 CSRF Token；
- CSP、禁止 iframe、禁止 MIME 嗅探、严格 Referrer 和 no-store 响应头默认开启；
- Tushare Token、数据库 DSN、Web 密码不进入 HTML、JSON、日志、异常或审计负载；
- 写操作保存请求人、范围、时间、结果摘要和审计事件；
- `AQ_LIVE_TRADING_ENABLED=true` 时拒绝启动本阶段控制台；
- 不提供订单创建、撤单、资金划转或实盘开关。

## 3. 交互与接口

### 页面

- `/`：系统状态、数据覆盖、控制记录摘要和能力边界；
- `/data`：证券、日期范围查询和收盘价/成交量可视化；
- `/ingestion`：受限采集表单与任务列表；
- `/trading`：显示执行账本、QMT 网关和风控尚未实现，所有交易按钮禁用。

### API

- `GET /healthz`：不含依赖详情的存活探针；
- `GET /api/v1/overview`：数据库状态与数据/控制记录摘要；
- `GET /api/v1/bars`：单证券、最多 366 天的时点日线查询；
- `GET /api/v1/jobs`：最近采集任务；
- `POST /api/v1/jobs/daily-ingestion`：创建受限日线采集任务；
- `GET /api/v1/trading`：返回 `unavailable` 能力状态，不返回虚构交易。

## 4. 任务模型

PostgreSQL 保存 `operator_jobs`。任务状态只允许：

`queued -> running -> completed | failed | interrupted`

服务启动时将遗留的 `running` 任务标记为 `interrupted`，不自动重试，避免操作员未知情况下扩大供应商请求或写入范围。任务请求使用幂等键去重；单任务最多 20 只证券、366 个自然日。

## 5. 完成证据

- 未配置 Web 凭证时控制台拒绝启动；
- 未认证请求得到 401，未提供 CSRF 的写请求得到 403；
- API 不返回任何配置 Secret；
- 数据库不可用时概览降级显示 unavailable，写任务失败关闭；
- 日线查询强制 `as_of`，限制标的数量和日期范围；
- 在线采集在供应商响应完成后捕获有效 `as_of`；研究读取仍要求调用方显式提供历史时点；
- 采集任务产生状态记录与审计事件；
- 单元、API、数据库集成测试、Ruff 和 mypy 全部通过；
- 真实数据库与 Tushare 小区间任务完成后才声明控制台数据链路可用。

## 6. 后续交易页面解锁条件

只有完成以下能力，交易页面才可展示真实订单、成交、持仓和 PnL：

1. 离散事件现金/持仓/费用账本；
2. A 股 T+1、涨跌停、停牌、整手和成本模型；
3. 订单意图、双层风控和幂等状态机；
4. Windows XtQuant/MiniQMT 只读对账与模拟盘；
5. 独立安全评审、故障演练和人工启用租约。
