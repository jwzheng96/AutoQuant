# AutoQuant 模拟执行状态与对账核心设计

- 日期：2026-07-22
- 状态：领域核心、持久化、模拟券商与双源账户投影已实施；协调与调度循环待实施
- 安全边界：本模块不连接券商，也不提供 HTTP 下单入口

## 1. 风控决策到订单

模拟订单只能从 `paper` 模式且结果为 `accepted` 的不可变风控决策创建。订单保留
风控决策哈希、账户、客户订单号、标的、方向、数量、价格和批准时间，并生成订单
内容哈希。实盘或拒绝的决策不能转换为模拟订单。

## 2. 订单状态机

本地 `approved` 状态只能由系统创建，券商回报可推进到 `submitted`、
`partially_filled`、`filled`、`cancelled`、`rejected` 或 `unknown`。每个回报必须具有
同一账户、客户订单号、不可变券商订单号和单调递增的券商序号。

- 相同序号与相同内容是幂等重放，不生成新事件；
- 相同序号但内容不同、序号倒退或时间倒退立即拒绝；
- 累计成交量不能减少或超过委托量；
- 完全成交、撤单和拒单为不可逆终态；
- `unknown` 表示系统不能证明券商状态，此时上层必须停止新订单，直到更高序号的
  券商事实恢复状态，不能自行推断成交或撤单。

每次有效转换生成带前序哈希的事件，并更新投影哈希。PostgreSQL schema v8 在同一事务
中追加不可变事件并以乐观哈希更新订单投影；任何一步失败都会整体回滚。服务启动时
按事件顺序重新运行状态机，重放结果与持久化投影不一致时拒绝启动。

## 3. 账户对账

内部回报链与模拟券商事实链独立重建资金、权益、持仓总量、T+1 可卖量和未结订单，
并把来源事实、行情、初始资金、时间及费用版本提交到证据哈希。对账器按稳定顺序
检查：快照时效、各自资金平衡、现金、权益、持仓总量、T+1 可卖量、市值和未结订单
集合。误差只允许在显式金额容差内；任一问题都会令 `reconciled=false`，并由盘前
风控拒绝后续订单。

## 4. 下一步

订单、转换事件、账户快照和对账报告已原子持久化，并通过临时数据库验证幂等写入、
不可变触发器、双源差异检测与进程重建后的确定性重放。后续仍需把模拟券商、风控、
行情和 kill switch 接入单一协调器，并运行定时对账、断电恢复和紧急停机演练。在
这些证据完成前，交易页继续只读，QMT 与真实交易继续硬锁。
