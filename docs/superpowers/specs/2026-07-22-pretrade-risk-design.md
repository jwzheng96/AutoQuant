# AutoQuant 盘前风控与审计账本设计

- 日期：2026-07-22
- 状态：盘前核心与只读审计状态已实施；模拟盘和实盘网关未实施
- 安全边界：任何风控通过结果都不能直接触发真实委托

## 1. 目标

在模拟盘账户与 QMT 网关之前建立共享、确定性、失败关闭的盘前风控层。相同策略、
账户快照、行情快照、规则版本和风控版本必须生成相同决策哈希。所有决策先写入
不可变 PostgreSQL 账本，后续网关只能消费已审计的决策。

## 2. 输入与完整性

输入由订单意图、执行模式、版本化风控策略、账户快照、行情快照和 A 股交易规则
组成。账户快照必须满足现金加多头市值与权益对账；行情和账户时间必须使用 UTC
且未超过配置的新鲜度阈值。策略、账户和行情分别生成内容哈希，决策保存这些引用
以及完整的规范化载荷。

## 3. 硬限制

引擎一次返回全部稳定拒绝代码，覆盖：

- 实盘模式硬锁、紧急停机、对账异常、账户或行情过期、休市；
- 标的白名单、客户订单号去重、未来时间戳、未结订单数量；
- A 股买入手数、单笔最大数量、无持仓卖出和 T+1 可卖数量；
- 单笔金额、可用现金、单标的权重、组合总敞口和日换手；
- 日内亏损、账户回撤与订单价格偏离。

默认策略用于模拟盘准备，并不表示适合任意账户规模。任何阈值放宽都必须形成新的
策略版本和策略哈希，不能修改历史决策。

## 4. 持久化语义

`risk_decisions` 以决策哈希为主键，以 `(account_id, client_order_id)` 作为业务幂等键。
同一订单号重复提交相同内容返回原决策；内容不同则拒绝。数据库触发器禁止更新和
删除，读取时重新计算载荷哈希。数据库不可用或完整性验证失败时，系统不返回可用的
风控状态，也不得继续到执行网关。

## 5. 当前接口边界

`GET /api/v1/risk` 和交易页只展示锁定状态、审计数量、最近决策与剩余门禁。当前没有
创建订单、撤单或切换实盘的 HTTP 接口。`ExecutionMode.LIVE` 在引擎内部始终产生
`live_mode_locked`，避免通过界面或配置误开实盘。

## 6. 后续放行门槛

下一阶段依次实现：模拟账户状态机、可信报价适配器、订单状态机、成交与持仓对账、
紧急停机演练、重启恢复、QMT Windows 隔离网关，以及持续模拟盘证据。策略还必须
用更长历史和多个市场阶段通过独立样本外与成本压力测试。上述门槛全部完成前，
真实交易保持锁定，也不得宣称系统能够盈利。
